# RFC 7592 — OAuth 2.0 Dynamic Client Registration Management

- Status: Experimental · https://www.rfc-editor.org/rfc/rfc7592 · Conf: OPT

## Назначение
Управление динамически зарегистрированным клиентом по registration access token.

## Где в API
- `GET|PUT|DELETE /oauth2/register/{client_id}`
- `registration_client_uri` в ответе на регистрацию — это тот же URL

## Conformance
- Registration access token авторизует **ровно один** клиент — тот, для которого
  выдан. Предъявление его против другого `client_id` — 404, иначе токен был бы
  мастер-ключом по всем клиентам проекта.
- `PUT` — замена, а не патч (§2.2): поле, которого нет в запросе, очищается.
  Правильный порядок: `GET`, отредактировать результат, отправить обратно.
- `redirect_uris` остаётся обязательным и на обновлении.

## Gotchas
- Парный к [RFC 7591](rfc7591.md); без DCR не нужен.
- `GET` не переотдаёт `client_secret` — он выдаётся только при регистрации.
- Ротации registration access token нет: потерянный токен означает, что клиентом
  дальше управляют через admin API.
